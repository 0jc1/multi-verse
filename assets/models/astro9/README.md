# Astro-9 prototype models (V0.9.6)

| File | What | Made by | Licence |
|---|---|---|---|
| `spiral_tower.glb` | Gaudí-style spiral tower, 16 m (mosaic shell, stone buttresses, neon helix, chrome crown) | generated by `js/gfx_forge.js` | project's own work, no third-party content |
| `alien_zib.glb` | tall alien, 16-bone skeleton, clips Idle / Walk / Dance / Wave | generated by `js/gfx_forge.js` | project's own work |
| `alien_orbo.glb` | short one-eyed alien, same skeleton + clips | generated by `js/gfx_forge.js` | project's own work |

Rebuild them with `powershell -ExecutionPolicy Bypass -File tools\forge_glb.ps1` (headless Chrome + three.js r128 GLTFExporter), or open `tools/forge.html` over the local server and press the button.

## Replacing them with Blender models
The game looks materials up **by name** and swaps in its own PBR materials (`AV.forge.runtimeMat`), so a Blender export only has to use these names:

| Material name | Becomes |
|---|---|
| `mosaic` | trencadís mosaic (colour + normal + roughness maps, bright Gaudí palette) |
| `mosaic2` | pale trencadís (sand / blue), double-sided |
| `stone` | warm stone, rough |
| `chrome` | mirror metal (reflects the HDRI) |
| `neon` / `glow` | unlit glow, boosted ×5 / ×3.2 so it blooms |
| `skin` / `suit` / `eye` | character materials (the file's own colour is kept) |

Any other material name keeps the file's own material. For characters, keep the bone names (`hips, spine, chest, neck, head, antL, antR, uArmL, fArmL, uArmR, fArmR, thighL, shinL, thighR, shinR`) and the clip names `Idle`, `Walk`, `Dance`, `Wave`; the character faces +Z, Y is up, 1 unit = 1 m. Export as glTF Binary (.glb) with "Apply modifiers" and "Animations" on. If a file is missing or broken, the procedural version is used instead.
